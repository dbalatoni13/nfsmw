# Segunda tanda del 14/09: referencia C de VP6 y dos hipótesis descartadas

## Resultado integrado

Se sustituye una declaración con nombre ASM artificial por la función C real:

```c
extern void ClearSysState_C(void);
/* En UtilMachineSpecificConfig: */
ClearSysState = (VP6_FUNC)ClearSysState_C;
```

En `uoptsystemdependant.c` desaparece
`gcc2_compiled_ClearSysState asm("gcc2_compiled._8034E180")`.
En `vputil.c` se retira la definición ASM de ese marcador inventado por el
troceador. `ClearSysState_C` ya era una función C real y empezaba en el mismo
offset `.text+0`; no se crea otra función ni se copia ensamblador a un array.

**Alcance exacto de limpieza:** una construcción `asm("nombre")` retirada y
su etiqueta artificial asociada. El bloque ASM de reservas de datos de vputil
permanece: no se cuenta como un segundo bloque eliminado ni como datos ya
reconstruidos en C. No se introducen atributos de sección, variables auxiliares,
pines, barreras o cambios de flags.

El mismo censo léxico sobre 3.679 ficheros confirma exactamente una construcción
menos, categoría nombre de enlace (499 -> 498). Datos, instrucciones, barreras
y pines no cambian. Foto final: `scratchpad/codex_20260914_tanda2/census_after.json`.
Se conservan CRLF en vputil y LF en uoptsystemdependant.

El análisis de las 619 entradas del grafo confirma un único proveedor del
marcador (vputil) y dos relocaciones en un único consumidor
(uoptsystemdependant). No hay otro consumidor de ese alias al que dejar sin
definición. Las dos relocaciones pasan a la función real, con el mismo tipo,
addend y destino efectivo.

## `lbmpeg`: inicialización directa no genera el constructor

La hipótesis `namespace Snd { int MPEGuse_MMX(0); }` se midió con los flags
reales. Produce 0 B de código, sin `.ctors` ni relocaciones runtime. El objetivo
necesita los dos cuerpos de inicialización, 84 B en total. **No se integra.**
La recompilación del ASM actual sí coincide con su objeto entero de producción.

Además, r61c atribuye los cuatro bytes finales de la `.data` actualmente
asignada a lbmpeg a la unidad siguiente, mpegl3base. No se debe inventar otra
variable para rellenarlos. La propiedad del rango y la forma original del
inicializador siguen abiertas. No se han cambiado splits ni se ha inventado un
helper, una lectura volatile o una variable para obligar al constructor a salir.

Detalle y reproducción:
`scratchpad/codex_20260914_tanda2_lbmpeg/report.md` y `audit.py`.

## `_IHandle`: cuerpo exacto, regresiones en llamadores

Declarar `IGenericMessage::_IHandle` fuera de línea y definirlo al final de
zFe2 produce sus 12 B exactos y las dos relocaciones correctas, pero oculta el
cuerpo al compilador cuando procesa los llamadores. En nueve funciones HUD
aparecen llamadas en vez de integrar el retorno de dirección. La `.text` crece
56 B; se pierden nueve funciones exactas (5.728 B de objetivo).

Retirar la definición temprana también cambia DECL_UID en -3: aparecen
16 referencias locales indefinidas cuyos cuerpos ASM conservan los sufijos
previos. No se parchean esos callbacks, porque no arreglaría las nueve
regresiones. **No se integra el cambio de cabecera.**

La baseline fresca de zFe2 coincide con producción entera. Los siete
consumidores hallados mediante cadenas DWARF no son un inventario exhaustivo:
zPhysics incluye la cabecera y no apareció en ese grep. No se recompilaron
otros consumidores; las regresiones locales bastan para descartar esta forma.

Detalle, nueve funciones y artefactos:
`scratchpad/codex_20260914_tanda2_ihandle/report.md`.

## Continuación y límites

Se mantiene el orden: ASM -> C/C++ legítimo, 100 % match y después 100 % linked.
Las negativas anteriores descartan esas formas concretas, no toda solución C.

- Para lbmpeg hace falta evidencia del inicializador original, no otra variante
  de cero ni un helper inventado para generar escritura runtime.
- Para `_IHandle` hay que explicar su emisión fuera de línea conservando el
  cuerpo visible para inline y sin perturbar las clases locales; la forma de
  declaración tardía medida aquí no lo consigue.
- Otros alias deben revisarse con sus consumidores reales. `stdio.c`, por
  ejemplo, documenta referencias desde objetos extraídos; no se extrapola el
  éxito de VP6 para borrarlo sin resolverlas.
- Continúa abierto el lote de datos ASM; hay que conservar identidad, binding,
  secciones y propiedad, no sustituir reservas por variables ficticias.
